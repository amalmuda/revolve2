# Quality metrics per run

Per-run smoothness (HHS), straightness (EM), and balance for every CMA-ES run,
computed by re-simulating the saved best controller for 30 s in MuJoCo and
recording physics traces. No re-evaluation of fitness or modification of saved data.

## Metric definitions (taken from existing scripts)

- **smoothness** = `hhs` (Head Height Stability), defined in `compute_hhs.py` as
  the cumulative absolute change in core z-position over the simulation:
  `HHS = Σ |pz(t+1) − pz(t)|`. Unit: meters. **Lower is smoother** (less vertical
  bouncing). Range: ≥ 0.
- **straightness** = `em` (Effective Movement), defined in `compute_em.py` as
  displacement / total path length: `EM = D / T`. Range [0, 1]. **Higher is
  straighter**; 1.0 = perfectly straight, lower = more wandering.
- **balance** = Kargar et al. (2021) balance metric, defined in `compute_balance.py`:
  `B = 1 − (Σ|roll| + Σ|pitch|) / (n_steps × 360)` with roll/pitch in degrees clamped
  to [0, 180]. Range [0, 1]. **Higher is more balanced**; 1.0 = perfectly level.

## Source files

- `balance_results.txt`, `hhs_results.txt`, `em_results.txt` — uncoupled / neighbour /
  structured runs (computed previously by the corresponding `compute_*.py` scripts).
- `_fc_quality_metrics.txt` — fully-connected runs (computed by
  `compute_fc_quality_metrics.py`, which runs all three metrics in one simulation pass).
